# Changelog

All notable changes to the Allin1 Super App are recorded here.

## \[Unreleased]

### Fixed

- patch — Custom Hotel checkout was completely broken: `custom_hotel_orders` (written by `CustomHotelService.placeOrder`/`linkServiceRequest`) had no `firestore.rules` block, so every write hit the catch-all deny and the customer's "Place Order" tap died with permission-denied before the `service_requests` dispatch doc was ever created. Added a rules block (create = real user with matching customerId / admin; read = ordering customer, owning seller, or admin; update = customer may only attach `serviceRequestId` via a `hasOnly()` pin, seller/admin full; delete = admin only).
- patch — Sellers never received the loud "New Order Received" foreground alert: `seller_live_alert_service.dart` queried top-level `sellerId`, but `createServiceRequest` stores the seller uid nested at `details.sellerId` (and writes no top-level field), so the query matched zero documents. Fixed to filter `details.sellerId` and moved the `createdAt > session-start` cutoff into the listener so the new equality-only query needs no new composite console index.
- patch — Food/grocery/custom orders deadlocked at `hero_assigned`: the hero's "Start" action waits on `estimateApprovedByCustomer == true`, but the customer approve/negotiate UI existed only in `hero_booking_tracking_screen.dart`. Extracted the estimate card into a shared `lib/widgets/estimate_approval_card.dart` and surfaced it in `ServiceRequestTrackingScreen` (the tracking screen all food/grocery/custom orders use), so customers can approve or counter-offer and unblock the hero. `hero_booking_tracking_screen.dart` now uses the same shared widget (no more drift risk).
- patch — A seller's custom-food menu rendered in two places: the global "Custom Hotels" grids in `food_hub_screen.dart` and `custom_food_order_screen.dart` (both from `openHotelsStream()`) duplicated the seller's own shop menu from `category_screen` → `seller_detail_screen`. Removed both global grids; custom food now renders ONLY inside the seller's own shop page via a new "Custom Menu" card in `seller_detail_screen.dart` that opens `CustomHotelViewScreen` (the custom_hotel_order checkout pipeline is untouched).
- patch — Global Food Theme Overhaul: recolored the last dark-themed screens in the customer food flow to the brand 'Pure White + Vibrant Hot Pink' palette — `seller_detail_screen.dart` (scaffold/cart sheet/dialogs/FAB/checkout), `product_card.dart`, `category_screen.dart`, `seller_card.dart` (food accent red → hot pink), `empty_state.dart`, `order_photo_gallery.dart` (muted tone + placeholder box). The legacy/unreachable food-order screens were also recolored for consistency (`cart_screen.dart`, `checkout_screen.dart`, `order_tracking_screen.dart`, `biriyani_menu_screen.dart`) — pure UI-only, no logic/query/routing changes.

- patch — Customer app no longer gets stuck on the Payment screen after the Hero marks payment as received. `payment_screen.dart`'s `paymentStatus` gate (both the live listener and the lifecycle-resume poll) was missing the `'settled'` and `'confirmed'` values that the Hero-side `_markPaymentReceived()` flow writes, so the customer never unlocked into the rating screen. Added `onError` handling to the ride-status stream listener so a failed snapshot subscription surfaces in logs instead of failing silently.
- patch — Same root cause on the Hero side: `hero_history_screen.dart`'s `paymentSettled` getter and `hero_home_screen.dart`'s one-time "payment received" notification trigger were also missing `'settled'`/`'confirmed'`, so a Hero could still see "Report Payment Issue" as available on an already-settled ride, and never saw the in-app payment-confirmation banner after using the newer `_markPaymentReceived()` flow.
- patch — Customer app's Recent Activity screen (`ride_history_screen.dart`, dashboard drawer → "Activity") always showed "No rides yet!" for every customer, on every ride. The query filtered on a `userId` field that the `rides` schema never consistently writes (only `customerId` is guaranteed present on every ride document); fixed to filter on `customerId`. Also fixed the card display, which read stale/nonexistent field names (`pickup`, `drop`, `rideType`) instead of the actual schema fields (`pickupAddress`, `dropAddress`, `category`) — the ride-type icon now matches against the canonical category keys (`bike`/`auto`/`car`/`parcel`/`mini_truck`/`lorry`/`emergency_manpower`) per AGENTS.md Section 3, instead of the old capitalized `'Auto'`/`'Parcel'` strings that never matched actual data.
