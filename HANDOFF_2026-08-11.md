## 2. Verification convention (no compiler available)

After editing any Dart/JS/PowerShell file:

```bash
python3 -c "s=open('FILE').read(); print('parens',s.count('('),s.count(')'),'braces',s.count('{'),s.count('}'))"
```

**Known false positive:** a few files have a pre-existing 1-paren imbalance
from an unmatched `(` inside comment prose (e.g. `auth_service.dart`,
`hero_register_screen.dart`). Before assuming you broke it, compare:

```bash
git show HEAD:FILE | python3 -c "import sys;s=sys.stdin.read();print(s.count('('),s.count(')'))"
```

Balance checks catch typos. They do **not** catch type errors — always ask the
user to run `flutter analyze` before building.

## 3. Recurring bug classes in this codebase — check for these first

These have each bitten multiple times. When debugging, suspect them early.

1. **Swallowed errors.** `catch (e) { return null; }` with no log. Root cause
   of at least four "it silently does nothing" bugs. Always surface the real
   error.
2. **Firestore composite indexes.** `.where()` on one field + `.orderBy()` on
   a different field needs a composite index and throws
   `failed-precondition`. Fix by dropping `.orderBy()` and sorting
   client-side — do not add indexes this close to launch.
3. **Collection-group queries need their own rule.** A nested
   `match /a/{id}/b/{id2}` rule does **not** authorize
   `collectionGroup('b')`. Needs `match /{path=**}/b/{id2}`.
4. **Missing rules = silent default-deny.** Several collections had zero rule
   coverage. If something reads "permission denied", check the rule exists
   before debugging the code.
5. **Assumed function signatures.** Always grep the real signature. A wrong
   guess at `resolveCustomerPhone(User)` cost a build cycle.
6. **Stale build artifacts.** Weird shader/compile failures are usually fixed
   by `Remove-Item -Recurse -Force .dart_tool\flutter_build, build\web`.
7. **PowerShell `$LASTEXITCODE` after `flutter.bat`** is unreliable through a
   pipeline. Don't trust it alone for destructive decisions.

## 4. Architecture decisions already made — do NOT undo these

- **Admin analytics are fetch-on-demand, never live streams.** Screens load
  the last snapshot from Hive on open; Firestore is touched only when the
  admin taps **Fetch**. Shared widget:
  `lib/widgets/admin/cached_analytics_view.dart`. This is a deliberate
  Spark-quota decision — do not reintroduce `StreamBuilder` there.
- **Usage fee model** = infra cost recovery (₹0.05/online-minute + ₹2/task),
  NOT a % commission. `lib/services/hero_wallet_service.dart`.
- **Hero presence** lives in RTDB `online_heroes/{uid}` only (not Firestore).
  `onDisconnect()` **stamps** `connectionLost`, it does not delete — customer
  search keeps disconnected heroes for a 5-minute grace window.
- **Firestore web transport** is forced to long-polling
  (`webExperimentalForceLongPolling: true`) in all 4 `main_*.dart` — some
  networks block QUIC.
- **Splash:** HTML splash in `web/index.html` (shared by all 4 flavors).
  Repeat visits detected by a `localStorage` check that MUST stay first in
  `<head>`. Flutter splash video plays on first-ever launch only.
- **Service worker** (`web/pwa_fallback_sw.js`): network-first for HTML,
  **stale-while-revalidate for heavy bundles** (`main.dart.js`, fonts,
  canvaskit). Cache name is stamped per-flavor-per-deploy by `deploy_web.ps1`.
